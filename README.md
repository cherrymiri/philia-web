# PHILIA — 친구의 사랑

졸업전시 〈When Love Responds, 사랑의 응답〉 세 번째 사랑. 2인 3각 인터랙티브 웹 (Three.js + Vite).

## 실행

```bash
npm install
npm run dev        # 개발 서버 → http://localhost:5173
npm run build      # 배포용 빌드 → dist/
npm run preview    # 빌드 결과 확인 → http://localhost:4173
```

Node.js 18 이상이 필요합니다.

## Vercel 배포

**방법 1 — GitHub 연동 (추천)**
1. 이 폴더를 GitHub 저장소에 올립니다. (`node_modules`, `dist` 는 `.gitignore` 로 제외됨)
2. vercel.com → Add New → Project → 저장소 선택
3. Framework Preset 이 **Vite** 로 자동 인식됩니다. 그대로 Deploy.
   (Build Command `npm run build`, Output Directory `dist`)

**방법 2 — 터미널**
```bash
npm i -g vercel
vercel          # 처음 한 번: 질문에 기본값으로 답하면 됨
vercel --prod
```

## 구조

```
public/models/PHILIA_model_v1.glb   Blender 모델 (그대로 사용)
src/main.js        장면, 카메라, 밴드 변형, 반사, 판정→움직임→착지→발자국→물결, 엔딩, 다시 걷기
src/rhythm.js      리듬 엔진: 패턴 조합, PERFECT/GOOD/MISS 판정, SYNC, 친구 실수 이벤트 (화면과 분리된 순수 로직)
src/walk.js        2인 3각 걸음, MISS 휘청거림, 친구가 버텨 주는 동작, 친구의 헛디딤과 도와주기
src/notes.js       다가오는 리듬 노트(맨발 자국) + 판정선
src/glass.js       우윳빛 유리 + 얇게 빛나는 외곽선 재질
src/floor.js       어두운 수면 바닥 + 물결 셰이더
src/footprints.js  걸어온 맨발 자국 (인스턴싱, 최대 220개 재사용)
src/style.css      UI (PC / 모바일 반응형)
```

### GLB 사용 방식
- 신발 4개(`Shoe_B_L`, `Shoe_B_R`, `Shoe_A_L`, `Shoe_A_R`)와 `Band_Link` 를 각각 독립적으로 움직입니다.
- 카메라가 신발 뒤에서 앞(-Z)을 보므로 화면 왼쪽부터:
  `Shoe_B_L`(첫 번째 사람 바깥 발) · `Shoe_B_R`(첫 번째 사람 안쪽 발) · `Shoe_A_L`(두 번째 사람 안쪽 발) · `Shoe_A_R`(두 번째 사람 바깥 발)
- 화면 왼쪽 사람 = 관람객 = **버터 옐로우**, 오른쪽 사람 = 가상의 친구 = **피치 핑크**.
- 밴드는 두 안쪽 신발을 따라 매 프레임 변형되고, 발이 어긋나거나 휘청일 때 팽팽해집니다.
- Blender 의 Cycles 외곽선 발광은 glTF 로 내보내지지 않으므로 `glass.js` 에서 Fresnel 외곽선으로 다시 만들었습니다.

## 리듬게임 (src/rhythm.js)

- 맨발 자국 노트가 화면 안쪽에서 다가오고, 신발 앞 바닥의 얇은 빛의 선(레인마다 둥근 영역)에 닿을 때 누릅니다.
  - 왼쪽 레인 = 왼발 자국(버터빛) = `왼발` 버튼 = 양쪽 바깥 발 2개
  - 오른쪽 레인 = 오른발 자국(피치빛) = `오른발` 버튼 = 묶인 가운데 발 2개
- 판정: PERFECT ±120ms, GOOD ±250ms, 그 밖(너무 이른 입력·반대 발·놓침)은 MISS. 모바일 터치는 25ms 보정합니다.
- 패턴은 미리 설계한 리듬을 이어 붙입니다. 초반은 느린 번갈아 걷기, 중반부터 `왼·왼·오른`, `오른·왼·오른·오른`, `왼·쉬기·오른` 등이 섞이고, 후반은 안정적인 리듬입니다.
- 실수가 이어지면 판정 범위가 넓어지고 쉬운 패턴으로 돌아갑니다.
- SYNC 는 판정으로만 오릅니다. PERFECT 2.0, GOOD 1.7, 연속 성공 보너스가 있고, MISS 는 증가 없음(감소도 없음)입니다. 노트와 상관없는 입력은 아무 영향이 없습니다.
- 서툰 관람객을 위해, 실수가 많았거나 30초가 넘어가면 성공 1회의 무게가 조금씩 커집니다. 성공해야만 오르므로 시간만으로는 끝나지 않습니다.
- 노트를 3개 연속 놓치면(아무도 누르지 않으면) 대기 상태로 멈추고 안내 문구가 다시 나옵니다. 아무 버튼이나 누르면 이어집니다.

### MISS → 휘청거림 → 친구가 버텨 줌 (src/walk.js)
1. 실수한 쪽 관람객 발이 앞으로 튀어나가며 앞코가 쏠림
2. 묶인 두 발이 함께 끌려가 기울고, 밴드가 팽팽해짐
3. 넘어질 뻔한 자세로 잠깐 멈칫
4. 친구의 바깥 발이 바깥쪽 앞으로 한 걸음 크게 디뎌 버팀 (착지 물결)
5. 친구가 먼저 안정되고, 관람객 발이 따라서 다시 나란히

- 이 동안(약 0.9~1.3초) 노트와 판정 시계가 멈춥니다. 재개 후 다음 노트까지 1초 이상 여유를 줍니다.
- SYNC 가 높을수록 휘청거림이 작아지고 더 빨리 회복합니다.

### 친구의 실수 (한 번만)
- SYNC 50% 를 넘긴 정상 판정 직후, 친구의 안쪽 발이 헛디뎌 기울어지고 밴드가 당겨집니다.
- 노트와 판정이 멈추고 노트가 흐려지며, `친구에게 발을 맞춰주세요.` 와 함께 `오른발` 버튼이 숨쉬듯 빛납니다.
- 오래 기다려도 MISS·감소가 없습니다. 반대 버튼을 눌러도 아무 일이 없습니다.
- `오른발`을 누르면 관람객의 안쪽 발이 받쳐 주며 함께 착지하고, 더 크고 따뜻한 물결이 퍼집니다. 유대감 보너스로 SYNC +4.

**시뮬레이션 결과** (실제 `rhythm.js` 사용, 각 4회)

| 플레이어 | 100% 도달 |
|---|---|
| 능숙 (타이밍 오차 ±40ms) | 29~31초 |
| 보통 (±90ms, 가끔 놓침) | 33~42초 |
| 서툼 (±140ms, 10% 놓침, 8% 반대 발) | 48~59초 |
| 매우 서툼 (±200ms, 20% 놓침, 15% 반대 발) | 67~83초 |
| 무작위 연타 | 100초 이상 또는 완료 안 됨 |
| 입력 없음 | 완료 안 됨 (0%) |

난이도는 `src/rhythm.js` 맨 위의 상수로 조절합니다.
- `WIN_PERFECT`, `WIN_GOOD`: 판정 범위
- `GAIN_PERFECT`, `GAIN_GOOD`, `COMBO_BONUS`: SYNC 증가량
- `APPROACH`: 노트가 나타나서 선에 닿기까지 시간
- `PATTERNS`: 리듬 패턴과 박자 길이

## 엔딩 / 다시 걷기
- 100% 가 되면 버튼 입력을 막고, 뒤에 있던 두 발이 마지막 걸음을 함께 내딛습니다. 큰 물결이 퍼지며 네 발이 나란히 멈춥니다.
- 카메라가 천천히 높아지며 물러나, 함께 걸어온 최근 발자국이 신발 뒤로 이어진 모습을 보여 줍니다. 앞쪽으로는 두 걸음만 아주 희미하게 암시합니다.
- `WE'RE BESTIES!` 는 화면 정중앙, 그 아래 `다시 걷기`.
- `다시 걷기`를 누르면 새로고침 없이 처음 상태로 돌아갑니다. 초기화되는 항목: SYNC, 색, 발자국, 물결, 카메라, 노트·패턴, 친구 실수 이벤트, 안내 문구, 버튼.
- 오브젝트를 새로 만들지 않으므로 여러 번 반복해도 쌓이지 않습니다.

## 성능
- 발자국은 인스턴싱 1개로 처리하고(최대 220개 재사용), 물결은 바닥 셰이더 안에서 계산합니다(최대 16개). 그래서 진행할수록 오브젝트가 늘어나지 않습니다.
- 모바일에서는 해상도 비율을 최대 1.5로 제한하고, 블룸을 절반 해상도로 처리합니다.
- 시작 후 3초 동안 프레임을 측정합니다.
  - 45fps 미만이면 해상도를 자동으로 낮춥니다.
  - 28fps 미만이면 블룸을 끕니다.
- 주소 뒤에 `?lite` 를 붙이면 블룸 없이 실행됩니다. 저사양 기기 확인용입니다.

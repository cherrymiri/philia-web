# PHILIA — 친구의 사랑

졸업전시 〈When Love Responds, 사랑의 응답〉 세 번째 사랑. 2인 3각 인터랙티브 웹 (Three.js + Vite).

## 실행

```bash
npm install
npm run dev        # 개발 서버 → http://localhost:5173
npm run build      # 배포용 빌드 → dist/
npm run preview    # 빌드 결과 확인 → http://localhost:4173
```

Node.js 18 이상이 필요합니다.

## Vercel 배포

**방법 1 — GitHub 연동 (추천)**
1. 이 폴더를 GitHub 저장소에 올립니다. (`node_modules`, `dist` 는 `.gitignore` 로 제외됨)
2. vercel.com → Add New → Project → 저장소 선택
3. Framework Preset 이 **Vite** 로 자동 인식됩니다. 그대로 Deploy.
   (Build Command `npm run build`, Output Directory `dist`)

**방법 2 — 터미널**
```bash
npm i -g vercel
vercel          # 처음 한 번: 질문에 기본값으로 답하면 됨
vercel --prod
```

## 구조

```
public/models/PHILIA_model_v1.glb   Blender 모델 (그대로 사용)
src/main.js        장면, 카메라, 밴드 변형, 반사, 착지→발자국→물결, 엔딩, 다시 걷기
src/walk.js        2인 3각 걸음, 가상의 친구, SYNC 판정
src/glass.js       우윳빛 유리 + 얇게 빛나는 외곽선 재질
src/floor.js       어두운 수면 바닥 + 물결 셰이더
src/footprints.js  맨발 자국 (인스턴싱, 최대 220개 재사용)
src/style.css      UI (PC / 모바일 반응형)
```

### GLB 사용 방식
- 신발 4개(`Shoe_B_L`, `Shoe_B_R`, `Shoe_A_L`, `Shoe_A_R`)와 `Band_Link` 를 각각 독립적으로 움직입니다.
- 카메라가 신발 뒤에서 앞(-Z)을 보므로 화면 왼쪽부터:
  `Shoe_B_L`(첫 번째 사람 바깥 발) · `Shoe_B_R`(첫 번째 사람 안쪽 발) · `Shoe_A_L`(두 번째 사람 안쪽 발) · `Shoe_A_R`(두 번째 사람 바깥 발)
- 화면 왼쪽 사람 = 관람객 = **버터 옐로우**, 오른쪽 사람 = 가상의 친구 = **피치 핑크**.
  (GLB 안의 이름 A/B 와 상관없이 화면 위치 기준으로 색을 정했습니다)
- 밴드는 두 안쪽 신발의 움직임을 따라 매 프레임 변형됩니다. 가운데는 살짝 늦게 따라오고, 두 발이 어긋나면 팽팽해집니다.
- Blender 의 Cycles 외곽선 발광은 glTF 로 내보내지지 않으므로 `glass.js` 에서 Fresnel 외곽선으로 다시 만들었습니다.

## 체험 설계 (src/walk.js)

- 버튼을 누른 그 이벤트 안에서 관람객의 발 애니메이션이 시작됩니다 (다음 화면 프레임에 바로 보임).
- 친구의 발은 처음엔 약 0.2초 늦고 보폭도 조금 달라 발자국 간격이 불규칙합니다. SYNC 가 오를수록 같은 순간, 같은 보폭으로 걸으며 발자국도 규칙적인 패턴이 됩니다.
- 같은 버튼 반복: 걸음으로 인정하지 않음. 발이 제자리에서 머뭇거리고 친구는 기다립니다. SYNC 는 첫 실수에 0.3%만 줄고 초기화되지 않습니다.
- SYNC 는 시간 기준으로 증가합니다. 빠르게 연타해도, 천천히 걸어도 비슷한 시간이 걸립니다.
- 같은 그룹의 두 발이 거의 동시에(0.09초 이내) 닿으면 두 물결이 하나의 큰 파동으로 퍼집니다.

**시뮬레이션 결과** (실제 `walk.js` 로직 사용)

| 입력 패턴 | 100% 도달 |
|---|---|
| 0.5초 간격 일정하게 | 33초 |
| 0.8초 간격 | 34초 |
| 0.4~0.8초 자연스러운 리듬 | 35초 |
| 1.3초 느리게 | 36초 |
| 불규칙 + 같은 버튼 실수 15% | 약 48초 |
| 0.12초 연타 | 89초 (연타로는 빨라지지 않음) |
| 같은 버튼만 | 도달하지 않음 (0%) |
| 입력 없음 | 도달하지 않음 |

난이도 조절은 `src/walk.js` 맨 위의 상수로 합니다.
- `SYNC_RATE`: 높이면 더 빨리 끝남
- `SPAM_INTERVAL`: 연타로 인정하지 않는 간격
- `LEAD`: 보폭

## 엔딩 / 다시 걷기
- 100% 가 되면 버튼 입력을 막습니다.
- 뒤에 있던 두 발이 마지막 걸음을 함께 내딛고, 큰 물결이 퍼지며 네 발이 나란히 멈춥니다.
- 카메라가 위로 올라가며 물러나, 함께 걸어온 발자국과 앞으로 멀리 이어지는 발자국 길을 보여줍니다.
- 그다음 `WE'RE BESTIES!`, 이어서 `다시 걷기` 가 나타납니다.
- `다시 걷기`를 누르면 새로고침 없이 처음 상태로 돌아갑니다. 초기화되는 항목: SYNC, 색, 발자국, 물결, 카메라, 친구의 리듬, 안내 문구, 버튼.
- 오브젝트를 새로 만들지 않으므로 여러 번 반복해도 쌓이지 않습니다.

## 성능
- 발자국은 인스턴싱 1개로 처리하고(최대 220개 재사용), 물결은 바닥 셰이더 안에서 계산합니다(최대 16개). 그래서 진행할수록 오브젝트가 늘어나지 않습니다.
- 모바일에서는 해상도 비율을 최대 1.5로 제한하고, 블룸을 절반 해상도로 처리합니다.
- 시작 후 3초 동안 프레임을 측정합니다.
  - 45fps 미만이면 해상도를 자동으로 낮춥니다.
  - 28fps 미만이면 블룸을 끕니다.
- 주소 뒤에 `?lite` 를 붙이면 블룸 없이 실행됩니다. 저사양 기기 확인용입니다.
